# XLB Thermal Fluid Workbench

汎用モデル形式で組み直した独立プロジェクト。モデルツリー、設定、グラフィックス、計算履歴を分離したCOMSOL風ワークベンチです。旧 `../xlb_gui` のコード・保存データには依存しません。

## 起動

初めてセットアップする場合は、リポジトリを取得します:

```sh
git clone https://github.com/Syb04/XLB-GUI-Docker.git
cd XLB-GUI-Docker
```

ソースはリポジトリ直下に配置しています。実行データの `data/` と個別の `.env` はGit管理対象外です。

計算中の速度・圧力・温度の変化は [残差モニター](docs/residual-monitor.md) で確認できます。許容値を連続して満たしたかを表示し、全履歴をCSV保存します。

重力・温度差による浮力は「物理モデル」から有効にできます。CPU／CUDA／GPU＋RAM、温度依存密度、リスタートに対応します。設定と圧力の定義は [重力・浮力ガイド](docs/gravity.md) を参照してください。

このPCではDocker＋GPU版を使用し、既存の `data/` を引き継ぎます:

```powershell
cd H:\20260902_XLB\xlb_workbench
.\start-docker.ps1 -Gpu -LocalData
```

ブラウザで <http://127.0.0.1:8766> を開きます。旧GUIの8765番ポートと分離しています。

Dockerを使わず、このPCの既存WSL環境でCPU版を起動する場合:

```powershell
.\start.ps1
```

同じポートで別のサーバーが動いている場合は先に終了してください。`start-docker.ps1` はWindowsにDockerコマンドがなければWSL Ubuntu-24.04のDocker Engineを使います。`-Port 8767` でポートを変更できます。`-LocalData` を省略した場合はDockerの名前付きボリュームを使います。

別のマシンでは、Docker Engine / Docker DesktopとComposeを用意し、このディレクトリで:

```sh
docker compose up --build -d
```

CPUで実行可能です。NVIDIA GPUを使う場合は、ホスト側のドライバーとNVIDIA Container Toolkitを準備し:

```sh
docker compose -f compose.yaml -f compose.gpu.yaml up --build -d
```

解析設定で `cuda:0` を選択してください。DockerイメージにXLB、Warp、Gmsh、NumPy等を含めます。XLBはコミット `9470e54a8d7ccd68d8e5563ca7a573040841ea8c` に固定。インターネット接続が必要なのは初回ビルド時です。依存関係の直接バージョンは `requirements.txt` に固定していますが、OSと全推移依存の完全な再現ロックではありません。

保存データはComposeの `workbench-data` ボリュームに残ります。`docker compose down` では保持されます。移行時は画面からZIPを書き出し、移行先の画面で読み込んでください。

Dockerを使わず新しいLinux環境に入れる場合:

```sh
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m workbench.server
```

STEP/IGES読込のGmshにはLinuxの `libglu1-mesa`、`libxft2` 等が必要です。Dockerfileを参照してください。

## 解析の流れ

1. 新規モデルを作成し、箱形領域またはCADを指定。CADはインポート時に長さ単位を選択します。
2. 物性を入力。密度、粘度、比熱、熱伝導率は定数または温度と物性値の表で定義します。
3. 流れ・熱輸送の有効化、使用物性、初期温度を設定します。「流体の計算法」は格子ボルツマン法（LBM、D3Q27・BGK）です。「流体モデル」で層流またはSmagorinsky LESを選択します。温度場は有限体積法で解き、LBMの速度場と連成します。
4. モデルビューで箱の6面またはCADの個別面をクリックし、境界条件を割り当てます。選択面の強調表示と面名で対象を確認します。
5. 「目標総セル数」を入力すると等方格子の各軸分割数を自動計算します。実際の総数・X/Y/Z分割数・セル幅を確認してメッシュを生成します。総数は流体だけでなく固体・領域外セルを含みます。整数分割のため目標値とは差が出ます。既存の各軸指定は総数を編集するまで維持します。ボックスの寸法は変更せず、上限内で等方分割できない寸法比にはエラーを返します。CAD流体領域は等方格子への丸めによる外側余白を含みます。
6. 時間刻み・ステップ数・履歴出力間隔・途中結果保存間隔・計算デバイスを設定して保存・実行します。スタディには格子幅と境界速度から求めたLBMの時間刻み上限を表示します（格子マッハ数0.30未満）。時間刻みを変更すると、同じステップ数で進む物理時間も変わります。計算失敗時は結果画面の「計算の停止理由」を確認してください。セル数の等方丸めは正常な調整として情報表示します。
7. 計算中も保存済みステップを選択・再生し、速度成分・圧力・温度・渦度・熱流束・物性値の断面を表示できます。[使い方と容量の目安](docs/transient-results.md)を参照してください。最終結果はNPZ、VTK、CSVでも出力できます。
8. モデルと結果をZIPで書き出します。計算中は先に停止または終了してください。

保存済みサンプルは `examples/heated_channel.xlb.zip`。画面の「読み込み」で条件と200ステップの計算結果を開けます。条件だけのJSONは `examples/heated_channel.json` です。

スタディの「CFLからの推奨 Δt」は、指定した各速度境界の `|ux|/dx + |uy|/dy + |uz|/dz` の最大値から目標CFL=0.1となる時間刻みを求め、LBMマッハ数上限に対応する時間刻みの80%以下に制限します。現在のCFLと推奨値を表示し、入力済みのΔtは変更しません。圧力境界だけの場合など非ゼロの速度指定がなければ算出不能と表示します。推奨値は移流に関する目安であり、内部流速の増加、熱拡散・壁面の熱損失、温度依存物性やBGK緩和時間の制約を保証するものではありません。

## 対応範囲

これは汎用化のための動作する初版であり、Fluent/COMSOLと同等の全物理・精度保証を持つ製品ではありません。

|機能|範囲|
|---|---|
|形状|箱、閉じたSTL/OBJ、GmshによるSTEP/IGES/BREPの表面三角形化|
|領域|単一流体、CAD内部の流体体積、箱内のCAD障害物、材料を割り当てた固体領域|
|格子|XLB用の等間隔直交ボクセル格子。非構造四面体格子・局所細分化なし|
|流れ|XLB演算子を使う3D非圧縮近似LBM。層流／Smagorinsky LES、速度入口、圧力出口、静止壁|
|熱|流体の移流・拡散と固体熱伝導の共役計算。固定温度、断熱、熱流束、対流熱伝達|
|物性|温度表の線形補間。密度は非圧縮基準密度として扱う制約あり|
|保存|入力スナップショット、実装ハッシュと環境バージョン、格子、指定間隔の途中場、最終場、反復履歴、状態、元CAD。ZIP移行|

圧縮性、多相流、放射、相変化、移動メッシュは未実装です。重力・浮力は非圧縮近似の範囲で対応します（[制約と設定](docs/gravity.md)）。乱流モデルはSmagorinsky LESで、RANSのk-ε／k-ωや壁関数は含みません。形状が閉じていない場合や格子で境界を解像できない場合はエラーにします。

温度表の範囲外は端点値で固定します。物性や時間刻みが安定性条件を満たさないときは、実行を失敗として記録します。`completed` は指定ステップの完了を示し、定常収束や工学精度の保証ではありません。曲面壁はボクセル近似なので、形状・格子依存性の確認が必要です。旧円管ソルバーの精度検証結果をこの新規ソルバーへ転用していません。

### 乱流・固体・CAD面

水・乾燥空気には温度依存／20 °C定数の物性プリセットがあります。材料画面からCSV物性表の読み込みも可能です。温度範囲、出典、CSV列形式は [docs/material-properties.md](docs/material-properties.md) を参照してください。

- 流体モデルで「Smagorinsky LES」を選び、モデル定数と乱流Prandtl数を指定します。速度勾配から渦動粘度を求め、流れの緩和時間と熱拡散係数へ反映します。LESには対象の渦と壁面を解像する格子・時間刻みが必要です。粗い格子でモデルを有効にしただけでは乱流精度を確認したことにはなりません。
- 箱領域には、位置・寸法・材料を指定した複数の直方体固体を追加できます。CADを障害物として使う場合は、その内部に固体材料を割り当てられます。流体・固体界面は両側の熱伝導率から熱抵抗を計算し、等量逆向きの熱流束で接続します。固体内部には流速を与えません。
- STEP/IGES/BREPはCADの面タグを保持します。STL/OBJには元のCAD面定義がないため、連結した同一平面の三角形をパッチとして扱います。曲面のSTLは多数のパッチになります。元の曲面単位で選びたい場合はSTEPを使用してください。
- 境界の面選択では `cad:<面ID>` が個別面、`cad` が残りのCAD面の既定条件です。面IDはインポートしたアセットに属します。別ファイルとして再インポートした場合は選択を確認してください。
- 同じ格子接触面では、明示した箱の境界条件、個別CAD面、CAD既定条件の順に優先します。共役熱伝達で接続された流体・固体界面には、入口・出口や外部の熱源条件を重ねられません。その界面の既定壁条件では、材料間の熱伝導が有効です。
- CAD境界はボクセルの接触面へ写像します。曲面適合格子ではなく、熱流束の面積もボクセル面積に基づきます。個別のCAD入口・出口は境界セルの分布関数を再構成する近似で、形状と解像度に対する収束確認が必要です。

固体の物性も同じ材料エディターを使います。固体材料の粘度欄は形式上保持しますが、固体の熱伝導計算には使いません。

CPU版でもXLBを使って流れを計算します。`cuda:0` 指定時はLBM・熱輸送・LES・温度依存物性をGPUで処理します。メッシュ生成と結果ファイルの書き出しはCPUです。通常の反復ではGPUで集計した値だけを取得し、指定した途中保存ステップと最後の保存時に計算場をまとめて取得します。完了・停止時には再開用の分布関数と内部状態も保存します。

VRAMに収まらない場合は解析設定の **GPU＋RAM（大規模・低速）** (`cuda:0-ram`) を選べます。全体をRAMに保持し、衝突計算をバッチごとにGPUへ送り、移流・熱・LESはCPUで処理します。RAM容量と転送・CPU処理が新しい制約になります。バッチセル数、WSLのRAM割り当て、診断の詳細は [docs/ram-compute.md](docs/ram-compute.md) を参照してください。

### 計算時間の延長（リスタート）

結果データで完了または停止済みの実行を選び、「リスタート」で追加ステップ数を入力して「追加計算を開始」を押します。追加時間と延長後の終了時刻を確認できます。例えば時間刻み0.001秒・終了ステップ200の結果へ100ステップを追加すると、0.2秒から0.3秒まで計算します。結果のステップ番号・時刻は元の計算からの累積値です。

元の実行に保存された格子・時間刻み・物性・境界条件を引き継ぎ、別の実行として結果を保存します。編集中のプロジェクト条件や元の結果は上書きしません。延長後の結果からさらに延長でき、プロジェクトZIPにも再開データが含まれます。

再開には `restart.npz` と元の `mesh.npz`・`input.json` が必要です。プロット用の速度・圧力から初期化し直す処理ではなく、LBM分布関数（FP32）と温度の内部状態（FP64）を保持します。その分、完了時の保存量と保存時間が増えます。途中のプロット保存点からの再開、強制終了・計算失敗からの復旧には対応しません。機能追加前の実行には再開用データがないため、一度新しく計算してください。

GPU化の測定結果と比較手順は [docs/gpu-pipeline.md](docs/gpu-pipeline.md) を参照してください。

## 構成・検証

### 大きなメッシュと上限設定

既定は **総セル数1,000万、各軸1,024** です。旧版の200万セル制限を引き上げました。
Dockerでは `.env.example` を `.env` にコピーし、必要な値を変更して
`start-docker.ps1 -Gpu -LocalData` で再起動してください。Linuxでは同じCompose構成で `up --build -d --wait` を実行します。

```dotenv
XLB_MAX_TOTAL_CELLS=10000000
XLB_MAX_AXIS_CELLS=1024
XLB_MAX_BOUNDARY_LINK_MIB=512
```

Dockerを使わない場合は、これらをサーバー起動前の環境変数に設定します。
`/api/health` と新しいGUIのメッシュ設定欄で有効な上限を確認できます。
CAD面の境界配列には別途512 MiBの上限があります。これらは受付制限であり、
同じセル数でのソルバー実行に必要なRAM・VRAMを保証するものではありません。
300万セルの生成試験と現状の性能上の制約は [docs/mesh-scaling.md](docs/mesh-scaling.md) を参照してください。

- `workbench/schema.py`: プロジェクトと物性の検証
- `workbench/geometry.py`: CADインポート、単位変換、格子化
- `workbench/solver.py`: XLB流れ、熱輸送、場の保存
- `workbench/server.py`: HTTP API、実行キュー、保存、ZIP入出力
- `static/`: 外部CDN不要のブラウザGUI
- `tests/`: 物性・CAD・数値計算・HTTPと保存の試験

```sh
python -m unittest discover -s tests -v
node --check static/app.js
```

実測した検証結果と未確認項目は [docs/verification.md](docs/verification.md) に記録します。

Docker/GPUのセットアップと検証コマンドは [docs/docker-gpu.md](docs/docker-gpu.md) を参照してください。

数値ライブラリの一次資料: [XLB公式リポジトリ](https://github.com/Autodesk/XLB)、[Gmsh公式マニュアル](https://gmsh.info/doc/texinfo/)。ライセンスは各依存ライブラリの配布条件に従います。
