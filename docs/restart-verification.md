# リスタート検証（2026-09-17）

`scripts/verify_restart_gpu.py` をCUDA Dockerイメージと実機GPUで実行し、7ステップ連続計算と3ステップ＋4ステップ追加計算を比較した。

| ケース | LBM分布関数 FP32 | 温度内部状態 FP64 | 出力速度・圧力・温度・渦動粘度 |
|---|---|---|---|
| Smagorinsky LES＋固体共役熱伝達 | ビット一致 | ビット一致 | 全配列一致 |
| 熱のみ | ビット一致 | ビット一致 | 全配列一致 |
| 流れのみ | ビット一致 | ビット一致 | 全配列一致 |

格子は8×4×4、流体120セル・固体8セル、Δt=0.001 s。追加計算の保存ステップは3、4、6、7、終了時刻は0.007 s。実行デバイスは `cuda:0`。詳細値は [restart-gpu-verification.json](restart-gpu-verification.json) に保存した。この一致は同じ実装・ハードウェアでの短い回帰試験であり、任意ケースの安定性や異なるGPU間のビット一致を保証するものではない。

HTTP試験では2→5→7ステップの再開、元の結果の不変性、編集中のプロジェクト条件の保持、ZIP書き出し／インポート後の再開と実行IDの付け替えを確認する。不正な追加数、再開データのない旧実行、破損ファイルは再開できない理由を返す。

WSLのXLB/JAX環境で全94件の試験が成功（50.944 s）。その後に加えた熱のみの再開2件を含め、`tests.test_restart` の7件も成功（10.691 s）。CPU版・CUDA版Dockerイメージをビルドし、ポート8766のCUDA版を更新した。ブラウザで追加2ステップを指定し、3→5ステップの完了、0.005 sの最終場、再延長可能表示まで確認した。実行IDは [restart-ui-run.json](restart-ui-run.json) に記録した。

再開データは最終／正常停止時の `restart.npz` にのみ保存する。分布関数27×FP32と温度FP64で、圧縮前の配列は116 bytes/cell（300万セルで約348 MB）。圧縮後の容量は場による。通常の途中プロットには分布関数を追加しない。GPUでは最終結果の転送に分布関数もまとめるため、通常反復中の全場転送回数は増えないが、完了時の転送量・圧縮時間・ホストメモリは増える。
